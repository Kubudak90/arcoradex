## Deploy notes — broadcast resilience

Two operational findings worth flagging for future broadcasts on Arc
testnet:

1. **`txpool full` mid-script**: `forge script ... --broadcast` defaults
   to in-flight batching that overwhelms the testnet mempool's per-EOA
   slot limit. The first DeployV07 broadcast ran the protocol triple
   (Registry / Pool / Gateway) plus the first 5 token + feed pipelines
   cleanly, then `txpool full` cut the run between EURC seeding and
   TRYC token deploy. Always pass `--slow` (sequential, one-at-a-time
   submission) for any multi-tx broadcast.

2. **Ghost listing from a half-deployed CREATE address**: the original
   broadcast had pre-signed the BRLC token deploy + listToken at a
   nonce-derived predicted address (`0xD100...`). The token deploy tx
   never landed but the registry's `listToken(0xD100..., ...)` did,
   leaving a "ghost" entry pointing at an undeployed contract. Cleanup:
   `deactivateToken(0xD100...)`, then deploy real BRLC at a fresh
   address (`0x4dF26D0E...`) and re-list. Registry slot 6 now holds
   the inactive ghost; slot 7 holds the live BRLC. Frontend / keeper
   code that iterates `tokens()[i]` MUST filter on `isActive`.

## Keeper deployed (Task 15)

- Source: `ops/keepalive/multi-feed-push.mjs` (Node + viem ESM).
- Host: `194.163.136.1`, path `/root/arcora-v07-feeds/`.
- Service: `arcora-v07-feeds.service` (oneshot) +
  `arcora-v07-feeds.timer` (every 30 min, `OnUnitActiveSec=30min`).
- First fired manually at `2026-05-01T10:27:33Z`; next scheduled fire
  cycles every 30 min thereafter.
- Pushes 6 live CoinGecko prices into the mock feeds; USDC stays
  hardcoded at $1.0000 peg. Per-feed try/catch isolates 429 / network
  errors so a single bad fetch never breaks the run.

**Stale-feed discovery (2026-05-01 ~12:30 CEST).** Quote calls reverted
~80 minutes after the first keeper tick. Root cause: USDC's hardcoded
peg never changes value, so the keeper's "skip if unchanged" branch
never re-pushed and `latestUpdatedAt` aged past the pool's 1 hour
`MAX_STALE_SECONDS`. Same trap latent for any feed whose CoinGecko
price happens to round to the previous value. Patched in
`fix(ops): keeper bumps stale feeds even when value unchanged`
(commit 4f30ee1) — keeper now reads `latestUpdatedAt` and refresh-pushes
once the on-chain age exceeds 30 minutes.

**Cross-FX verified live.** TRYC → BRLC pay flow (no USD intermediate;
both 6 dec, both FX-pegged): 250 BRLC invoice ⇒ 2127.03 TRYC pulled,
250.00 BRLC out of pool, 249.75 BRLC to merchant + 0.25 BRLC gateway
fee (10 bps of received). Round-trip consistency on USDC↔EURC: 99.91 %
net of 5 bps × 2 pool fees, exact to integer rounding.

**Deviation widening note.** Live CoinGecko vs the deploy-time seed
prices showed wide drift: EURC ~+7%, TRYC ~−22%, BRLC ~−2%. The
on-chain `lastAcceptedPrice` (set during smoke pay flows) was at the
seed values, so the next swap involving these tokens would have
reverted under the original 150 bps PriceGuard tolerance. Mitigation:
`StablecoinRegistry.setDeviation(EURC|TRYC|BRLC, 5000)` (50%
permissive testnet bps). Future-work: the keeper should push step-wise
updates capped at the per-token deviationBps so the registry can stay
on production-grade tolerances.
